AirLLM Complete Guide: Run 70B Models on a 4GB GPU

In August 2026, AirLLM has become the most popular open-source large language model inference framework worldwide, with over 27,205 GitHub stars and more than 500,000 total downloads. Its core promise is simple yet extraordinary: run 70B parameter models on a single 4GB consumer GPU without quantization, distillation, or pruning.

The latest version v3.1.0 (released July 29, 2026) now supports Kimi K3 (2.8T) — the largest open-source model ever released — requiring only 3.72GB VRAM on a single RTX 6000 Ada. It also supports DeepSeek-V3 (671B), Llama 3.1 405B, and other massive models.

This comprehensive guide will walk you through everything you need to know about AirLLM, including installation, supported models, performance benchmarks, configuration options, and practical usage tips.

What is AirLLM?

AirLLM is an open-source inference optimization framework developed by researcher Gavin Li. Its core innovation is Layer-wise Streaming Inference: instead of loading the entire model into GPU memory at once, AirLLM streams layers from disk to GPU on-the-fly, reducing VRAM requirements from terabytes to just gigabytes.

Compared to traditional approaches, AirLLM offers several key advantages:

  • No quantization needed: Most solutions require 4-bit or 8-bit quantization to reduce VRAM, which sacrifices model accuracy. AirLLM runs original precision models, maintaining full inference quality.
  • No distillation needed: No need to replace large models with smaller ones, avoiding performance loss from distillation.
  • No pruning needed: No model parameters are removed, maintaining complete model integrity.
  • Completely free: Open-source project under Apache 2.0 license, zero subscription fees, zero API call costs.
  • Multi-platform support: Supports NVIDIA GPUs (CUDA), Apple Silicon Macs (MLX framework), and pure CPU inference.

Apple Silicon Mac

For Macs with M1/M2/M3 chips, AirLLM supports inference through the MLX framework. Mac's unified memory architecture allows the GPU and CPU to share memory, meaning you can run 70B models on a MacBook Pro with just 16GB of memory.

Mac users need to additionally install MLX:

pip install mlx mlx-lm

CPU Inference

AirLLM also supports pure CPU inference, though it's slower. Suitable for users without a GPU or insufficient VRAM.

Quick Start: Three-Step Installation & Usage

Step 1: Install AirLLM

pip install airllm

If you want to use the Kimi K3 model, you'll need additional dependencies:

pip install compressed-tensors flash-attn
pip install torch==2.5.1  # Requires CUDA 12 version
pip install transformers==4.56.2  # Kimi K3 requires this version

Step 2: Write Inference Code

from airllm import AutoModel

# Load model (automatically downloads from Hugging Face)
model = AutoModel.from_pretrained("Qwen/Qwen3-32B")

# Or load larger models
# model = AutoModel.from_pretrained("deepseek-ai/DeepSeek-V3")  # 671B, ~12GB VRAM
# model = AutoModel.from_pretrained("Qwen/Qwen3-235B-A22B")   # 235B, ~3GB VRAM
# model = AutoModel.from_pretrained("moonshotai/Kimi-K3-Instruct")  # 2.8T, 3.72GB VRAM

input_text = ["What is the capital of France?"]

input_tokens = model.tokenizer(input_text,
    return_tensors="pt",
    return_attention_mask=False,
    truncation=True,
    max_length=1024,
    padding=False)

generation_output = model.generate(
    input_tokens['input_ids'].cuda(),
    max_new_tokens=200,
    use_cache=True,
    return_dict_in_generate=True)

output = model.tokenizer.decode(generation_output.sequences[0])
print(output)

Step 3: Start Inference

After running the code, AirLLM will automatically:

  1. Download the model from Hugging Face to local cache (~/.cache/huggingface/hub/)
  2. Split the model into layer shards and cache them locally
  3. Stream each layer to GPU for inference

The first run requires waiting for downloads and caching, which may take 10-30 minutes. Subsequent runs will use the cache directly, significantly improving speed.

Performance Optimization: Compression Mode for 3x Speed

AirLLM provides model compression functionality using block-wise quantization technology, which can improve inference speed by up to 3x with almost imperceptible accuracy loss.

Enabling Compression Mode

from airllm import AutoModel

# Enable 8bit compression (recommended, minimal accuracy loss)
model = AutoModel.from_pretrained("garage-bAInd/Platypus2-70B-instruct",
                   compression='8bit')

# Or enable 4bit compression (faster, slightly lower accuracy)
model = AutoModel.from_pretrained("garage-bAInd/Platypus2-70B-instruct",
                   compression='4bit')

Compression vs. Quantization

Traditional quantization requires quantizing both weights and activations, which is difficult to maintain accuracy. AirLLM's compression only quantizes weights, because the inference bottleneck is primarily disk read speed, not computation speed. This approach is easier to guarantee accuracy, with practical tests showing almost imperceptible accuracy loss.

Troubleshooting

Issue 1: Insufficient VRAM

If your GPU VRAM is insufficient, try the following solutions:

  • Use compression='8bit' or '4bit' to enable compression mode
  • Reduce the max_length parameter to decrease context length
  • Use smaller models (e.g., Qwen3-32B instead of Qwen3-235B)

Issue 2: Slow First Load

The first run requires downloading the model and splitting layer shards, which may take 10-30 minutes. Subsequent runs will use the cache directly, significantly improving speed.

Issue 3: Kimi K3 Model Loading Failure

Kimi K3 requires specific dependencies:

pip install compressed-tensors flash-attn
pip install torch==2.5.1
pip install transformers==4.56.2

Issue 4: Insufficient Disk Space

Model cache occupies significant disk space. If space is insufficient, set delete_original=True. AirLLM will automatically delete the original model files and only keep the split layer shards, saving approximately 50% space.

FAQ

Frequently Asked Questions

Q: Is AirLLM completely free?
Yes, AirLLM is completely free. It is an open-source project under the Apache 2.0 license, requiring no subscription, API key, or paid account. You can run large language models locally an unlimited number of times at zero cost.
Q: What GPU do I need for AirLLM?
With 4GB VRAM, you can run 70B models (like Llama 3.1 70B, Qwen3-32B). With 8bit compression enabled, you can attempt larger models. DeepSeek-V3 (671B) requires at least 12GB VRAM.
Q: How does AirLLM differ from Ollama?
Ollama primarily optimizes for smaller models (7B-70B) using GGUF format. AirLLM focuses on ultra-large models (70B-2.8T) and supports original precision models without quantization. The two can be used complementarily.
Q: Can I use AirLLM on Mac?
Yes. AirLLM supports Apple Silicon Macs using the MLX framework for inference. Mac's unified memory architecture allows using all memory as VRAM, so a 16GB MacBook Pro can run 70B models.
Q: How fast is AirLLM?
With 4bit or 8bit compression mode, inference speed can be improved by up to 3x. Without compression, speed depends on GPU performance, but it's faster than cloud API calls (no network latency). For 70B models on RTX 4090, expect approximately 10-20 tokens/second.
Q: How do I integrate with existing projects?
AirLLM provides an OpenAI-compatible API endpoint. You can set base_url to http://localhost:8080/v1 and use any library supporting the OpenAI API (like LangChain, LlamaIndex) for integration.
