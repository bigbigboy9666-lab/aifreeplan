AirLLM 完全指南：在 4GB GPU 上运行 70B 大模型

2026 年 8 月，AirLLM 已成为全球最受欢迎的开源大模型推理框架，GitHub 上已获得 27,205+ 颗星，累计下载量超过 50 万次。它的核心承诺简单而惊人：无需量化、蒸馏或剪枝，仅用 4GB 显存的消费级显卡即可运行 70B 参数大模型。

最新版本 v3.1.0（2026 年 7 月 29 日发布）更是支持了 Kimi K3 (2.8T)——这是迄今为止最大的开源模型，在单张 RTX 6000 Ada 上仅需 3.72GB 显存。此外还支持 DeepSeek-V3 (671B)、Llama 3.1 405B 等巨型模型。

这篇文章将带你全面了解 AirLLM，包括安装步骤、支持的模型、性能数据、配置选项以及实际使用技巧。

什么是 AirLLM？

AirLLM 是由研究者 Gavin Li（李昊文） 开发的大模型推理优化框架。它的核心技术创新是层级流式推理（Layer-wise Streaming Inference）：模型不需要一次性加载到 GPU 显存中，而是逐层从磁盘读取并推理，从而将显存需求从 TB 级降到 GB 级。

与传统方法相比，AirLLM 有几个关键优势：

  • 无需量化：大多数方案需要通过 4-bit 或 8-bit 量化来减少显存，但这会牺牲模型精度。AirLLM 可以运行原始精度模型，保持完整的推理质量。
  • 无需蒸馏：不需要用小型模型替代大型模型，避免了蒸馏过程中的性能损失。
  • 无需剪枝：不需要删除模型参数，模型完整性保持完好。
  • 完全免费：开源项目，Apache 2.0 许可证，零订阅费用，零 API 调用成本。
  • 多平台支持：支持 NVIDIA GPU（CUDA）、Apple Silicon Mac（MLX 框架）和纯 CPU 推理。

注意：首次运行时，AirLLM 会将模型拆分为层碎片并保存到 Hugging Face 缓存目录。请确保缓存目录有至少 2 倍的模型文件大小空间（例如 70B 模型约需 140GB 存储空间）。

Apple Silicon Mac

对于搭载 M1/M2/M3 芯片的 Mac，AirLLM 支持通过 MLX 框架进行推理。Mac 的统一内存架构允许 GPU 和 CPU 共享内存，这意味着你可以用 16GB 内存的 MacBook Pro 运行 70B 模型。

Mac 用户需要额外安装 MLX：

pip install mlx mlx-lm

CPU 推理

AirLLM 也支持纯 CPU 推理，但速度较慢。适合没有 GPU 或显存不足的用户。

快速开始：三步安装与使用

第一步：安装 AirLLM

pip install airllm

如果使用 Kimi K3 模型，还需要额外安装依赖：

pip install compressed-tensors flash-attn
pip install torch==2.5.1  # 需要 CUDA 12 版本
pip install transformers==4.56.2  # Kimi K3 需要此版本

第二步：编写推理代码

from airllm import AutoModel

# 加载模型（自动从 Hugging Face 下载）
model = AutoModel.from_pretrained("Qwen/Qwen3-32B")

# 或者加载更大的模型
# model = AutoModel.from_pretrained("deepseek-ai/DeepSeek-V3")  # 671B，约 12GB 显存
# model = AutoModel.from_pretrained("Qwen/Qwen3-235B-A22B")   # 235B，约 3GB 显存
# model = AutoModel.from_pretrained("moonshotai/Kimi-K3-Instruct")  # 2.8T，3.72GB 显存

input_text = ["北京是中国的首都，对吗？"]

input_tokens = model.tokenizer(input_text,
    return_tensors="pt",
    return_attention_mask=False,
    truncation=True,
    max_length=1024,
    padding=False)

generation_output = model.generate(
    input_tokens['input_ids'].cuda(),
    max_new_tokens=200,
    use_cache=True,
    return_dict_in_generate=True)

output = model.tokenizer.decode(generation_output.sequences[0])
print(output)

第三步：开始推理

运行代码后，AirLLM 会自动：

  1. 从 Hugging Face 下载模型到本地缓存（~/.cache/huggingface/hub/）
  2. 将模型拆分为层碎片并缓存到本地
  3. 逐层加载到 GPU 进行推理

首次运行需要等待下载和缓存，后续运行会直接使用缓存，速度大幅提升。

性能优化：压缩模式提升 3 倍速度

AirLLM 提供了模型压缩功能，使用分块量化（Block-wise Quantization）技术，可以在几乎不损失精度的前提下，将推理速度提升 3 倍。

启用压缩模式

from airllm import AutoModel

# 启用 8bit 压缩（推荐，精度损失最小）
model = AutoModel.from_pretrained("garage-bAInd/Platypus2-70B-instruct",
                   compression='8bit')

# 或启用 4bit 压缩（速度更快，精度略低）
model = AutoModel.from_pretrained("garage-bAInd/Platypus2-70B-instruct",
                   compression='4bit')

压缩 vs 量化

传统量化需要同时量化权重和激活值，这很难保证精度。而 AirLLM 的压缩只针对权重进行量化，因为推理瓶颈主要在于磁盘读取速度而非计算速度。这种方法更容易保证精度，实测精度损失几乎不可感知。

故障排除

问题 1：显存不足

如果 GPU 显存不足，可以尝试以下方案：

  • 使用 compression='8bit' 或 '4bit' 启用压缩模式
  • 降低 max_length 参数，减少上下文长度
  • 使用较小的模型（如 Qwen3-32B 代替 Qwen3-235B）

问题 2：首次加载慢

首次运行需要下载模型并拆分层碎片，可能需要 10-30 分钟。后续运行会直接使用缓存，速度大幅提升。

问题 3：Kimi K3 模型加载失败

Kimi K3 需要特定依赖：

pip install compressed-tensors flash-attn
pip install torch==2.5.1
pip install transformers==4.56.2

问题 4：磁盘空间不足

模型缓存会占用大量磁盘空间。如果空间不足，可以设置 delete_original=True，AirLLM 会自动删除原始模型文件，只保留拆分后的层碎片，节省约 50% 空间。

常见问题

常见问答

Q: AirLLM 完全免费吗？
是的，AirLLM 完全免费。它是开源项目，采用 Apache 2.0 许可证，无需任何订阅、API Key 或付费账户。你可以无限次本地运行大模型，唯一的成本是电费和硬件折旧。
Q: 我的 GPU 只有 4GB 显存，能运行多大的模型？
4GB 显存可以运行 70B 模型（如 Llama 3.1 70B、Qwen3-32B）。如果启用 8bit 压缩，还可以尝试运行更大的模型。DeepSeek-V3 (671B) 需要至少 12GB 显存。
Q: AirLLM 与 Ollama 有什么区别？
Ollama 主要针对小模型（7B-70B）进行优化，使用 GGUF 格式。AirLLM 专注于超大模型（70B-2.8T），支持原始精度模型，无需量化。两者可以互补使用。
Q: 可以在 Mac 上使用 AirLLM 吗？
可以。AirLLM 支持 Apple Silicon Mac，使用 MLX 框架进行推理。Mac 的统一内存架构允许使用全部内存作为显存，16GB MacBook Pro 即可运行 70B 模型。
Q: AirLLM 的速度如何？
使用 4bit 或 8bit 压缩模式，推理速度可提升 3 倍。未压缩模式下，速度取决于 GPU 性能，但比云端 API 调用更快（无需网络延迟）。对于 70B 模型，RTX 4090 上约 10-20 tokens/秒。
Q: 如何集成到现有项目中？
AirLLM 提供 OpenAI 兼容的 API 端点。你可以将 base_url 设置为 http://localhost:8080/v1，然后使用任何支持 OpenAI API 的库（如 LangChain、LlamaIndex）进行集成。
